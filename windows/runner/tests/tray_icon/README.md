# Windows tray artwork regression test

Requires Visual Studio 2022 Community C++ tools and Flutter's Windows ephemeral
headers/runtime (generated by `flutter build windows`). From the repository root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File windows/runner/tests/tray_icon/run.ps1
```

The harness includes the real production implementation in a test translation
unit, constructs `Attention` with a no-op messenger, and never starts the app or
adds an icon to the shell tray. AppWindows-only paths abort if unexpectedly used.

Checks:

- Abyss's plain icon is byte-identical to its embedded icon resource.
- The badged icon has a red center, reduces alpha in the surrounding ring, and
  preserves pixels outside the corner (allowing for subpixel edge coverage).
- BaoCode's plain/badged icons and taskbar badges (1, 9, 10) match the fixed
  pre-change revision's raw ARGB pixels, not a reimplementation of the renderer.
- 100 repeated plain/badged/taskbar icon render-and-destroy cycles leave both
  GDI and USER object counts unchanged.

The default baseline is pinned to the commit immediately before the fix, so the
comparison remains meaningful after the fix is committed. `-Revision <commit>`
can select a different baseline. Generated binaries, PNG previews, raw pixels,
and logs go under `build/tray-native-check` (or `-OutputDirectory <path>`).
